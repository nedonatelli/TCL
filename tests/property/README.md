# Property-based tests

Invariants that must hold across generated inputs, rather than assertions about
particular values: round trips that return the original, transformations that
preserve a norm, orderings that stay sorted. `hypothesis` generates the inputs
and shrinks any failure to a minimal reproducing example.

## What's here

| Module | Target | Invariants |
|--------|--------|------------|
| `test_serialization_properties.py` | `pytcl.io.serialize`, `pytcl.io.asdf_io` | msgpack/JSON/ASDF round trips are bitwise-exact; JSON rejects non-finite values before encoding |
| `test_coordinate_properties.py` | `pytcl.coordinate_systems.conversions.{spherical,geodetic}` | `cart2sphere`/`sphere2cart` and `geodetic2ecef`/`ecef2geodetic` round-trip across all three spherical `system_type` conventions, including poles, the antimeridian, and subnormal magnitudes |
| `test_assignment_properties.py` | `pytcl.assignment_algorithms.two_dimensional.assignment.hungarian` | matches a brute-force oracle for optimal cost (minimize and maximize), returns a valid injective pairing, and `total_cost` matches the selected entries |
| `test_filter_properties.py` | `pytcl.dynamic_estimation.kalman.linear.{kf_predict,kf_update}` | posterior covariance stays symmetric and PSD; a measurement update never increases `trace(P)` |

`_strategies.py` holds the shared generators (`finite_floats`, `float64_arrays`,
`track_histories`, etc.) so each module draws from the same bounds instead of
reinventing subtly different ones.

## Profiles

`conftest.py` registers two Hypothesis profiles and picks one based on the
`CI` environment variable (GitHub Actions sets `CI=true` on every runner by
default — no workflow configuration needed):

| Profile | Examples | Randomization | When |
|---------|----------|----------------|------|
| `ci` | 100 | `derandomize=True` — same seed every run | Any environment where `CI` is set |
| `dev` | 500 | Hypothesis's own random seed, example database on | Local runs (`CI` unset) |

`ci` exists so a red build is reproducible from the commit alone: the exact
same sequence of generated examples, and the exact same shrunk failure, on
every run. `dev` explores harder locally where a stalled run just costs you
time, not a debugging session for someone else. Both profiles disable the
per-example deadline — Numba JIT warm-up on first use of a compiled kernel
makes wall-clock deadlines flaky in a way that says nothing about
correctness.

`.hypothesis/` (Hypothesis's local example database and cache) is gitignored
— it is regenerated by any run and never has anything to say about another
machine's history.

## The narrowing rule

**When a generator finds a genuine counterexample, the response is: fix the
defect, or pin it with `@pytest.mark.xfail(strict=True)` plus a tracking
issue and a ROADMAP Known-Issues row.**

Shrinking the input domain — excluding the failing region from the strategy,
tightening a `st.floats()` bound, adding an `assume()` that quietly rules out
the case that broke — is forbidden. A generator narrowed until the failure
disappears is a test that passes by construction and verifies nothing; it is
strictly worse than no test, because it *looks* like coverage. This directory
found exactly this shape of near-miss twice (see the `test_coordinate_
properties.py` module docstring for both): the exact-north-pole and
subnormal-elevation cases stayed in the generators, and the assertions split
by regime instead — pinned as permanent example-based regressions under
`derandomize`, not generated away.

Every counterexample a property test finds gets promoted to a permanent
example-based regression test beside the property that found it, so the
specific failing input stays pinned under `ci`'s derandomized run even after
whatever made it rare stops being generated on a given seed.
